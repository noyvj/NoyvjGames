# For Claude: working with the local AI

The owner has a local model (Devstral Small 2, 24B, via Ollama + Aider) on their Windows
laptop. It does small, exact code changes overnight or when Claude usage has run out.
Claude's job is to (1) hand it well-sized tasks and (2) review what it produces.

## What the local model can and cannot do
- It holds about 24k tokens. To edit a file it must read all of it.
- OK: any file under ~17k tokens. That is every game.py under ~1,700 lines (Lighthouse,
  Rule Finder, Hull Repair, Lexis, Mirror Lab, Teach the Machine, Stranded, Station Medic,
  Reaction Bench, Picture Grid, Robot Script, Pocket Bazaar, Constellations, Logic Gates,
  Evidence Hunt, Dead Reckoning, Heist Committee, Signal), and most index.html / style.css.
- NOT OK: game.py of Tide, Grid, Herd, Thaw, Loop, Drift, Aftermath, SOL, Canopy,
  Continuum, Trade Empire, Le Champ de Mots, Chronicle (75k-146k tokens).
- It is a much weaker coder than Claude. It does well with one exact change
  ("after line X add Y", "add function f that does Z, plus a test"), badly with design.
- It only ever touches games/<one game>/. pc.html is regenerated by its script.
- It never ticks TODO items and never touches main: each task is its own branch.

## 1. Handing it tasks: GitHub issues labelled `local-ai`
One issue per task. Keep each to one small, checkable change. Body format (exactly these
four keys, one per line; the task may continue on following lines):

    game: lighthouse
    item: QI-52
    files: index.html
    task: Directly after the line that includes ../../shared/site-settings.js, add
    <script src="../../shared/night-mode.js"></script> . Change nothing else.

    gh issue create --label local-ai --title "QI-52 lighthouse: night-mode include" --body-file task.md

Tips: name the exact files (`files:` is a comma list, may be blank), say exactly where the
change goes, say what test to add if Python changes, and split anything bigger into
several issues. The repo is public, so issue text is public.

## 2. Reviewing its work: draft PRs on branches `local-ai/...`
Each passing task becomes a draft PR titled `local-ai: <ITEM> <game>: <task>`, saying
"Closes #<issue>". The body has the run report (tests, changed files, time taken).

    gh pr list --search "head:local-ai/" --state open

Layout (spacing, blank lines) and, in its own new tests/test_ai_*.py files, unused imports and
variables are fixed by tools after the model finishes. When a test-writing task had some failing
tests, `salvage_tests.py` deleted just those and kept the rest if at least two still pass: the
report's "Salvage:" line names what was dropped. Check that what is left still tests something.

For each one: read the diff against the game's CLAUDE.md and the standing rules
(nothing timed, nothing lost, no luck for 100%, no audio files, saves load unchanged,
new save keys only when non-default and validated), run that game's tests, then
merge, fix on the branch, or close with a short reason. When a merge completes a
whole TODO item, tick it and run `python3 scripts/todo-progress.py`.
Tasks that FAILED get a comment on their issue instead of a PR.

## New games and hub registration (scripts, 2026-10-12)
- `python3 scripts/new_game.py <slug> "<Name>"` starts a game folder from `planning/<slug>-plan.md`
  (CLAUDE.md with the plan's milestone table, BUILD-STATUS.md, test setup); add `--page` when milestone 2
  starts for a minimal working page (index.html with the site includes, app.js, game.py with the save
  contract, tests). After that the local AI can build the milestones (make_todo_tasks.py queues them).
- `python3 scripts/register_game.py <slug>` registers a finished game on the hub in one command, from the
  design choices in `games/<slug>/register.json` (name, blurb, tags, colours, status line, smoke actions; the
  local AI can write that file). It edits every hub list, the service worker and the counting tests, runs the
  generators and the performance measurement, then the hub and smoke tests. `--dry-run` lists the changes.
  Tested on a throwaway copy with Slingshot: every step and test passed.

## 3. What the 2026-10-14/15 audits found (Claude session on the Mac, Noyvj)
Seven `stack-*` branches (about 100 Round 4 mobile and PC ideas) were audited. Of those, the audits kept about
half after rebuilding them (they had no tests and dead wiring), reverted about a fifth, and the model never
wrote about a fifth. See `local-ai/RULES.md` ("More mistakes from the audits") for what the model is told.
