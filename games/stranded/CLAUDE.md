# Stranded (working title)

You are Harbour, the plain voice on a thin text line to Ines Varga, a stubborn, funny field engineer alone on the small moon Orrin at the silent Sparrow Relay. Twelve days, 59 scenes, ten endings (nine warm or bittersweet, one sadder but gentle). Every reply gets an answer, nothing is timed, nothing is ever lost, and you can rewind to any of your messages for free. Personal project, no BCM tag, hub registration not done yet. Plan: `planning/stranded-plan.md` (TODO item QI-25). Read `BUILD-STATUS.md` first.

## Rules (owner's hard bans, all enforced by tests)
- No timers, energy, clocks, grinding, daily mechanics or randomness; replies arrive one per tap by default or all at once (a display setting, no timer).
- No on-screen death, no all-good hero (Ines overrode a warning light and avoids her brother's message), nothing that loses progress, no audio, no leaderboards, no generated images.
- Rewinding keeps the map, archive, endings and counters; only the three stats and flags go back (they are the state of that moment).

## Structure
- Story is data: `story_1..4.py` (S/C builders from `kit.py`; text shorthands in kit.py's docstring), `lore.py` (day titles, narrator lines, 29 collectables). The engine holds no story.
- `walker.py` is a pure deterministic stepper; the state is (scene, (trust, supplies, hope), flags), replayed from a string of choice numbers (the run's `path`).
- `explore.py`: `reach_all` (search over every reachable state, dominance-pruned, proves reachability), `route_to`, `loose_end`, `peek`. Edges are (scene, choice, target) triples so conditional routes count as separate paths.
- `game.py`: `handle(json)`, `get_state()`, `load_state()`; save = path, taken edges, seen scenes, endings, found ids, tally; validated field by field, new keys only when non-default, `achievements_earned` written never read.
- `app.js` is glue; `ENGINE_MODULES` must list every engine module in import order (a test checks).
- Desktop boot: `pc-config.json`, `pc.css`, `pc.js`; `pc.html` is generated (never edit by hand): import `scripts/generate-pc-pages.py` with importlib and write `build("stranded", cfg)`.

## Adding story
Add scenes to a story table; every non-ending scene needs 2 to 4 choices, each with a reply and at least one open choice; run `python3 -m pytest -q tests`. The graph tests prove every scene, edge, ending and collectable reachable, no cycles, no dead ends, and the lint refuses death, timer and energy words. Local Python is 3.9.

## For the local AI (exact names; every one was checked against the code on 2026-10-18)
- **Files**: engine `game.py` (entry point, `Game` class, `handle`, the whole view), `walker.py` (the pure stepper: `replay`, `available`, `visible`), `explore.py` (`reach_all`, `route_to`, `loose_end`, `peek`), `kit.py` (`S`/`C` scene builders), `story_1.py`..`story_4.py` (the 59 scenes as data) merged by `story.py` (`SCENES`, `EDGES`, `ORDER`, `ENDINGS`, `ENDING_IDS`, `START`, `DAYS`), `lore.py` (day titles, 29 collectables), `render.py` (SVG scene, portrait, map), `achievements.py`, `info.py`; page `index.html`, `app.js` (the whole page; engine module list `ENGINE_MODULES` at its top), `settings.js`, `pc.js`, `pc-config.json`, generated `pc.html`.
- **Entry points** (the only Python the page calls): `handle(json_string) -> json_string`, `get_state()`, `load_state(proxy)` (it then calls `window.strandedRefresh()`). In JS use `send({action: ...})` (app.js; it renders and saves). Never read a Python variable from JS by name. The answer is the WHOLE view; a bad request gives `{"error": ...}`. `game.py`'s docstring leaves out `difficulty`.
- **Actions** (`handle`; unknown name is `{"error": "unknown action ..."}`): `open` | `reset` | `choose {i}` (reply number counted from 0 in the current scene) | `rewind {step}` (step counted from 0) | `restart` | `goto {scene}` (a scene id already seen, e.g. `"d1a"`) | `peek` | `loose` | `hint` | `hint_do` | `difficulty {level}` (`easy normal hard`). A refused action returns the view with `ok: false` and a `message`.
  A new action = a branch in `handle`, the work in a `Game` method, a test, a line in the docstring. New story = scenes in a `story_N.py` table only (see "Adding story" above); the engine holds no story.
- **Top-level keys of the view** (`Game.view`): `ok message run stats choices transcript ending art portrait peek progress endings map archive tally hint about difficulty goals achievements map_svg`. `view.run`: `path steps day day_title days scene title flags`. `view.choices[]`: `i text tried ok why`. `view.transcript[]`: `kind text` (+ `day` or `step`), kinds `day narrator ines action you delta found`. `view.progress`: `scenes tried endings archive percent` (each a `[have, total]` pair except `percent`). `view.tally`: `rewinds peeks hints jumps sent`. `view.hint`: `rung max` plus `kind nudge hint answer do` as the rung rises.
- **get_state() keys** (only non-defaults): `path taken seen endings found tally achievements_earned` (`achievements_earned` is write-only). `path` is a string of choice digits; the rest is validated field by field in `Game.load`. Choices may only be appended to a scene, never reordered or removed (old saved paths replay by number).
- **Page**: `render()` in app.js draws one view (no event; add a `renderX()` it calls). Main ids: `#comms-panel`, `#chat` (messages), `#choices` (reply buttons, `data-testid` `stranded-choice-<i>`), the "Next message" button `data-testid` `stranded-next` (one message per tap is the default, so replies appear only after it is tapped through), `#ending-card`, `#restart-button`, `#hint-button`, `#hint-do-button`, `#peek-button`, `#loose-button`, `#action-line`, `#stats` (`#stat-day #stat-trust #stat-supplies #stat-hope`), `#progress` (`#stat-scenes #stat-paths #stat-endings #stat-archive`), `#tally` (`#stat-sent #stat-rewinds #stat-peeks #stat-jumps #stat-hints`, may be collapsed: read with `text_content`), `#goals`; window panels `#map-panel`, `#archive-panel`, `#achievements-panel`, `#changelog-panel`, `#settings-panel`, `#info-page-panel`; `#engine-status` is empty when the engine is ready.

## AN-17 (2026-10-11): difficulty choice (Easy / Normal / Hard)
- Owner answer Pq10. One shared start-of-game choice from `shared/difficulty.js` (`window.NoyvjDifficulty`, `shared/difficulty.css`, tests in `shared/tests/test_difficulty_browser.py`): a labelled radio group in `#difficulty-panel` / `#difficulty-slot` (a `<details>` open until a choice is made; in the Desktop boot it is the first block of the side column). Stored per browser and per game in `localStorage["difficulty:{slug}"]` (never in the save); `app.js` reads it at boot and on change and tells the engine with `{action: "difficulty", level}`; the engine keeps it in a module global (`difficulty`, default `"normal"`) that `reset` and `load_state` leave alone. Switching is allowed at any time (no mid-run lock needed in a puzzle game; `NoyvjDifficulty.setGuard` exists for a game that wants one).
- Design rule: difficulty changes only the surrounding pressure (help and medal bars), never the rules, the content or whether a puzzle can be finished. Normal is today's game: a test runs one scripted session with the level never told, told "normal", and after a detour through Hard and Easy, and requires byte-identical views and saves. Nothing is locked by any choice. Achievements and goals are always computed from the Normal records (so they stay reachable on Normal, and are the same whichever level was played).
- Stranded has no par, medals or seals, so the only knobs are help: Easy opens the nudge and the hint together on the first press and the What if? peek opens after one different reply tried in a scene (`explore.peek(state, taken, need)`, Normal and Hard need two); Hard has no answer step: `hint_do` and the map's "Show me a loose end" button (`loose`) are refused (the button is hidden and a note says why), ladder capped at 2. Scenes, replies, stats, flags and endings never change, so every ending stays reachable on Hard (the engine's own loose-end search is what the answer step used).
- Bug fixed on the way (Normal changes with it): `_hint()` used to put the nudge, the hint, the answer and the jump button into the view from the first press; each rung is now present only once asked for (`tests/test_difficulty.py` pins it). Achievements and goals are the same on every level (they read the one map and tally).
