# Loop — Circular Economy & Overconsumption Game

**Built following the shared conventions in `planning/archive/climate-quartet-2-plan.md`** (moved there 2026-09-22 once all four second-set games shipped; was `climate-quartet-2-plan.md` at the games root while build order still mattered). This file is Loop-specific only. Built third in this set — more structurally different from the others (redesigning a system rather than managing a rising meter), so built after the simpler patterns were solid.

## Concept

Unlike most of the other games in the hub, Loop isn't primarily about watching a meter rise or fall — it's about **redesigning a supply chain**. The player manages a production/consumption system: goods are made, used, and discarded by default. The player can invest in circular systems (repair, reuse, recycling loops) that reduce how much new raw-material extraction each cycle requires. The teaching moment is structural: waste isn't inevitable, it's a design choice built into how the system is shaped.

## Function tag: Systems to combat

This game exists to let the player ideate and build a *system*, not just respond to a threat. It should feel less like "manage a crisis" and more like "redesign the machine" — the player's satisfaction should come from watching a linear extract-use-discard chain become a closed loop, not from surviving a meter.

## Climate issue & hope angle

**Issue:** overconsumption and the emissions/extraction cost of a linear (take-make-waste) production economy.
**Hope angle:** this is naturally one of the easier games to make hopeful, since it's explicitly about building something better rather than staving off a threat. Lean into that — the visual and mechanical payoff of successfully closing a loop (less new extraction needed each cycle, same or better output) should feel like a genuine systems-design win, not just an emissions reduction.

## Core loop

- Turn-based rounds. Player manages a production chain: raw material extraction → manufacturing → consumer use → disposal, by default a straight line.
- Each round, player can invest in circularity infrastructure at different points in the chain: repair networks (extend product use-phase), reuse systems (route used goods back into manufacturing), recycling loops (recover raw materials from disposed goods).
- Each circularity investment reduces how much *new* extraction the next cycle needs to hit the same production target — this is the core payoff loop and should be the most visually satisfying feedback in the game.
- Extraction has an environmental cost meter (emissions/land damage) that rises with new-material use — same underlying "extraction is costly" logic as Canopy, but expressed through a supply-chain lens instead of a forest-plot lens.
- No hard fail-state. Scoring rewards how much of the production target is met via circular flow vs. new extraction by session end — a fully "closed loop" late-game state is the clearest win condition in the whole hub.

Rules for the split files:
- A variable a function reassigns lives in `loop_runstate.py` and is used everywhere as `runstate.x` (each module has `import loop_runstate as runstate`). Never `from loop_runstate import chain`.
- A new Python module: add it to `LOOP_PY_MODULES` in `boot.js`, to `_PART_NAMES` in `game.py` (dependency order), and to the precache in `sw.js` and `offline-manifest.json`.
- Tests that read the page or the stylesheet use `tests/pagefiles.py` (`page_text()`, `game_css()`), which join the split files.
- Monkeypatching in tests works through `game` (`monkeypatch.setattr(module, "_setting_number", ...)`): a write to `game.<name>` is copied to every module that holds that name.

## Standing constraints (short; the history is in `NOTES.md`)

- **Redesign a system, no fail state.** The payoff is a straight chain becoming a closed loop. Damage never heals but never ends the game; the zero-waste cap (`ZERO_WASTE_EXTRACTION_CAP`) is reported ("missed, play carries on") and never blocks anything. Score rewards circular supply over new extraction.
- **Nothing luck-gated.** Rules are deterministic: market shocks are a fixed schedule (`shock_for_cycle(n)`), the rival is a pure function of the cycle count, the narrator picks its line from the cycle number. The only random value is the cosmetic vignette start offset set in `setup()` (`runstate.vignette_session_offset`, 0 under pytest). Luck-based ideas (GH-17, GH-21, GH-30) wait for the owner.
- **Old saves always load.** Every save key added after the first contract is written only when it differs from a fresh chain and is read back with a safe `.get(...)` and a strict type/range check (a bad value loads as the default, and the H-27 load note says so). `summary`, `achievements_earned` and `lifetime_circular_fraction` are write-only. Browser preferences (effects, cracks, haptics, ring theme, confirm threshold, map views, ghost, panel memory) live in `settings.js`/localStorage, never in `get_state()`.
- **Career survives Start New Chain.** `chains_completed_count`, `goods_categories_tried`, `regional_hint_seen`, the career (`career_closed_categories`, `career_plates`, `career_speed`, `career_best`, `career_counts`) and `past_chains` are module-level and are NOT reset with the chain; a rewind does not rewind them. Relabel (H4) is cosmetic and never counts as a category tried; the secret Ship-Breaking Yard is kept OUT of `GOODS_CATEGORIES` (it is in `ALL_GOODS`) and can only be picked before the first cycle.
- **One notification at a time.** Closing the loop shows the banner first; an achievement earned by the same action waits `LOOP_CLOSED_BANNER_DURATION_MS` (user's answer, H13). Rewind re-seeds the toast baseline so it never pops a toast.
- **No hue-only meaning, motion is optional.** Bars are labelled, the rival's is striped, past-chain lines differ by dash pattern; every animation stops under reduced motion (in-game setting or OS), and effects ask `LoopSettings.effectsOn()` through `_setting_flag()`.
- **`hidden` must win.** `style.css` (the last stylesheet) has the blanket `[hidden] { display: none !important; }`; a class that sets `display` gets a `[hidden]` override next to it. Panels start hidden and open from a visible button.
- **Desktop page is generated.** `pc.html` comes from `index.html` + `pc-config.json` via `scripts/generate-pc-pages.py`; never edit it by hand.
