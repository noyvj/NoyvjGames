# Tide — Ocean Acidification & Sea-Level Rise Game

**Built following the shared conventions in `planning/archive/climate-quartet-plan.md`** (testing, feedback hook, hope-angle requirement, hub integration — moved there 2026-09-22 once all four quartet games shipped; was `climate-quartet-plan.md` at the games root while build order still mattered). This file is Tide-specific only. Built third of the four — the grid redraw was the most visually involved piece, built after Grid and Canopy's patterns were solid.

## Concept

You run a coastal settlement, balancing fishing/industry output against ocean health (an acidity meter) and a slowly rising sea-level line. The core teaching challenge here is **delayed consequence** — the damage from today's choices shows up late, which is exactly why acidification is hard for people to intuitively grasp in real life. The game should make that lag itself the lesson, not smooth it over for playability's sake.

## Climate issue & hope angle

**Issue:** ocean acidification and sea-level rise, and specifically the *delay* between cause and effect.
**Hope angle:** investment in adaptation infrastructure (seawalls, wetland restoration) should visibly slow the rate of sea-level encroachment and buy real time — not stop it outright (that would undercut the delayed-consequence lesson), but demonstrably change the trajectory. A player who invests early should see a flatter curve later, proving that acting now — even without immediate payoff — matters.

## Core loop

- Turn-based, seasonal cycles (simplest to implement and matches a settlement-management feel).
- Player allocates resources between: industry/fishing output (immediate income), acidity-reducing measures, and adaptation infrastructure (seawalls, wetland buffers).
- Acidity meter rises with industry output, falls (slowly) with dedicated reduction spending.
- Sea level rises on a slow background timeline, independent of player action *except* that adaptation infrastructure reduces its effective impact rate (not the rise itself — sea level keeps rising in the world, but well-adapted settlements are less damaged by it).
- **Grid redraw for sea-level rise:** implement this as a simplified tile-based coastline (a grid, not detailed art) where rows/tiles flip from "land" to "flooded" as the sea-level value crosses thresholds. This keeps the visual payoff (players can *see* the coastline shrink) without requiring real art assets — it's state-driven tile rendering, same pattern as Canopy's plot grid, just reading from a different variable.
- Fish stock (tied to acidity) acts as a slow-building consequence: high acidity eventually crashes the fishing yield, which is the player's own economy quietly punishing over-extraction — mirrors Canopy's "your own resource base collapses" lesson but on a longer delay.

## Standing rules a change must not break
- **Delayed consequence is the lesson.** Fish yield follows accumulated acidity on a lag; the damage from today's choices shows up late, and nothing may smooth that over (`tests/test_acidity_and_lag.py`, hard-lag mode in `tests/test_acidity_past.py`). Sea level keeps rising on its own timeline; adaptation only reduces its effective damage (`tests/test_sea_level_and_dampening.py`). Hope angle: early adaptation visibly flattens the damage curve (`tests/test_hope_angle_payoff.py`). No game over. Turn-based (seasons); nothing is timed.
- **Saves.** `get_state()` (`tide_savestate.py`) and `load_state()` (`tide_loading.py`) must load an old save that lacks any new key: read each field with a default, validate it (`_clamped_int`, `_finite_number` in `tide_bridge.py`), never trust list or dict shapes. New keys only when non-default (the existing code writes `coastline`, `daily`, `crew`, `chess`, `workshop` ... only when set). `summary`, `achievements_earned` and the coastline-kept field are write-only (never read back). Personal bests and the almanac live in localStorage, never in a save.
- No audio files; every new effect respects reduced motion and has an off switch. The page reads live numbers through Python functions, never `pyodide.globals.get("<state variable>")`.
- The module list lives in `TIDE_PY_MODULES` in `boot.js`; `_PART_NAMES` in `game.py` repeats it in the same order; `tests/test_file_sizes.py` checks both against the files on disk, the import order and the late-bound names. A variable that a function REPLACES lives in `tide_runstate.py` (and `LIVE_NAMES`), read as `runstate.x`. `SettlementState` is three mixins (`tide_model_town.py`, `tide_model_economy.py`, `tide_model_season.py`): a new method goes in the mixin for its topic.
- No file the AI may edit may pass about 14,000 estimated tokens (`tests/test_file_sizes.py`); `index.html` is capped at 16,000. `pc.html` is generated, never edited by hand. `shared/tests/test_hidden_attribute_rule.py` expects the blanket `[hidden]` rule at the start of `style.css`.

**State rule.** A module variable that some function REPLACES with `global x` / `x = ...` lives only in `tide_runstate.py`; every other module reads and writes it as `runstate.x` (each module starts with `import tide_runstate as runstate`). Never `from tide_runstate import x` (that copies the value once and goes stale). Lists, dicts and sets that are only changed in place (`_ghosts`, `_run_code_message`, `_harbor_rolls`) stay in the module that owns them. A new rebound variable goes in `tide_runstate.py` AND in its `LIVE_NAMES`. Tests use `game.state`, `game.graph_range = ...` and so on: `game.py` forwards reads and writes of the names in `LIVE_NAMES` to `tide_runstate`, and a write to any other name is copied into every module that holds that name (so `monkeypatch.setattr(game, "_read_local_storage_item", ...)` works).

**Late-bound names.** A few functions are called by an earlier module but defined in a later one: `get_state` (called by `set_checkpoint` in `tide_model_town`) and `render` (called by handler factories in `tide_libraryview` and `tide_flavour`). The earlier module holds a `name = None` placeholder and the later module (`tide_savestate`, `tide_renderer`) fills it in at the end of its own file. `tests/test_file_sizes.py` checks that wiring. Do not add more of these; put a new function in a module after everything it calls.

**Page files.** `index.html` is markup only (about 62 KB, the one file allowed above 14,000 tokens, capped at 16,000 by `tests/test_file_sizes.py`). Scripts: `tutorial-steps.js` (the walkthrough steps), `boot.js` (loads Pyodide, writes the Python modules, runs `game.py`, starts the tutorial and mobile HUD), `copy-wiring.js` (shared Copy result buttons and Credits links), `community-coastline.js` (R-30 fetch), `shortcuts.js` (keys and panels for the `?` help), `feedback.js` (the yes/no feedback prompt), then the older `settings.js`, `ui.js`, `pc.js`. Styles load in this order (the order is the cascade; Desktop's `pc.css` goes after the first `style.css` link): `style-1-base.css` (text scale, page shell, meters, tech tree, icon labels), `style-2-visuals.css` (the visual pass, console design pass 2, achievements), `style-3-panels.css` (changelog, toast, session summary, ticker, personal best, output mix, reduced motion, heritage tiles), `style.css` (the last part; starts with the blanket `[hidden]` rule that `shared/tests/test_hidden_attribute_rule.py` expects there, then accessibility, the ledger and the 2026-10-08 and later passes). ## For the local AI: exact names (verified against the code, 2026-10-18)
Tide has no `handle()` and no view dict: it is DOM-driven. `runstate.state` is the live `SettlementState` (`game.state` in tests); a click handler in `tide_handlers.py` changes it, then calls `render()`. The page code reaches Python only through `get_state`, `load_state` and a few functions looked up with `pyodide.globals.get(name)`.
- **Categories:** `CATEGORIES = ["output", "reduction", "adaptation"]`, `INVEST_COST = {output: 20, reduction: 25, adaptation: 30}`, `INVEST_LABELS` (all in `tide_rules.py`). `state.capacity` is a dict keyed by them. Five coastlines are in `COASTLINES` (`tide_rules.py`).
