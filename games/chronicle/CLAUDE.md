# Chronicle (working title)

Seed: `planning/chronicle-plan.md` (decisions at the top are binding) and `planning/TODO.md` section CH. Started 2026-10-07. Not tied to a BCM assessment. Hub registration, the Desktop boot (`pc.html`), the service-worker entry and the backend report table are NOT done here (later milestones).

## One-line pitch
A history game built from sets. A set is a folder of JSON (events, people, places, claims); the same engine plays every set, so a new topic is new data, not new code. The first set is a small SAMPLE about American presidents, marked "sample, draft until reviewed".

## Decisions that bind this folder
- General players, not a classroom product. Timeline builder first, then the cause web. One game with a set picker.
- **EVERY claim links at least three reputable sources** from at least two institutions, each with title, institution or author, URL and the date it was read. Validation fails the set otherwise (see `tests/test_set_format.py`).
- Facts are not copyrightable, sentences are: all text is original wording. Any fact shown names its sources on screen. Balanced and non-partisan on presidents: each moment is a dated, sourced fact, never praise or blame (a test scans for loaded words).
- No generated images (project rule): all art is inline SVG drawn by code (archive glyphs, the nuance strip, the favicon).
- No roguelike or deck mechanics. Deterministic and easy to 100%; effects have an off switch.
- Report a problem: a button on every claim. UI only for now: the engine builds a payload (`report.py`), the page saves a draft in localStorage (`chronicle:report-drafts`) and says "Reporting opens soon". NOTHING is posted anywhere (a test checks neither the engine nor app.js can reach a network). The backend table and admin list are CH-6.

## Stack
Python via Pyodide, plain HTML/CSS/JS, no build step. Engine modules have no DOM (the Signal / Lexis pattern): `handle(json) -> json` plus `get_state()` / `load_state()` for the shared save widget. `index.html` is a static shell; `app.js` loads Pyodide lazily after first paint, writes the set JSON and engine modules into Pyodide's file system (under `FS.cwd()`), runs `game.py`, and draws whatever view comes back. JS is not unit tested (no Node here); it is verified live.

## Modules
- `setdata.py`: the set format, `parse_date` / `sort_key` / `format_date`, `validate(files)` (every problem found, each prefixed with a stable code: `E_CLAIM_SOURCES`, `E_CLAIM_SOURCE_INCOMPLETE`, `E_CLAIM_INSTITUTIONS`, `E_SOURCE_FIELD`, `E_CONTRADICTION`, `E_EVENT_DATE`, `E_EVENT_DATE_CLAIM`, `E_EVENT_NO_CLAIM`, `E_ORDER`, `E_PLACE_UNSUPPORTED`, `E_PERSON_UNSUPPORTED`, `E_RELATION*`, `E_SECTION*`, `E_READING`, ...), `load_set` / `load_set_dict` (raise `SetError`), `ChronicleSet`.
- `puzzle.py`: the timeline builder's puzzles. A puzzle is a pure function of (set id, version, section, round), generated by a tiny splitmix64 (not `random`), pinned by `tests/fixtures/puzzles_v1.json` (regenerate with `python3 tests/make_fixture.py` only after bumping `SEED_VERSION`). Round r anchors on pool[r % n], so the first n rounds visit every event. `grade()` says right / wrong / empty per slot and which way a wrong card should move. `nuance()` lists the "elsewhere" events within the set's window of any card.
- `game.py`: the engine entry point (actions listed in its docstring), progress state, derived views, save/load (merge, never replace, never raise).
- `web.py`: the cause web's puzzles, the same pattern as `puzzle.py`: a pure function of (set id, version, chapter, round) using the shared splitmix64. Round r anchors on relation[r % n]; the other cards are seeded distractors; every relation between the chosen cards is a link to find. `judge()` says confirmed / reversed / unconfirmed ("not confirmed" never means "unrelated"). Pinned by `tests/fixtures/web_puzzles_v1.json`.
- `myth.py`: myth or record's puzzles, the same pattern: round r anchors on claim[r % n], the rest seeded, always at least one documented and one disputed/doubtful claim. The right bin is the claim's own `confidence`. Pinned by `tests/fixtures/myth_puzzles_v1.json`.
- `account.py`: whose account?'s puzzles, the same pattern: a pure function of (set id, version, account id, round). The page shows every passage of an account in one seeded display order (Passage A, B, C); round r puts display[r % n] in focus and asks up to five questions about its source (`who` wrote it: 4 options from the set's authors; `kind`: primary or secondary; `vantage`: what the writer could see; `purpose`: what the writer was trying to do; `left_out`: which point the passage omits, only when it omits one). Every answer is a choice from a fixed list built from the passage's own metadata, never free text. Pinned by `tests/fixtures/account_puzzles_v1.json`.
- `decision.py`: decision points. Nothing is graded; only the ORDER the options are shown in is generated (seeded, pinned by `tests/fixtures/decision_orders_v1.json`) so the authored order never gives the real choice away.
- `review.py`: spaced review (idea, not code, of Le Champ de Mots' scheduler). Items are learned facts (`ev:` a moment's date, `my:` a sorted statement, `ln:` a found cause link, `dc:` a decision made); the ladder is 1, 3, 7, 14, 30 days; a wrong answer returns the fact tomorrow and never removes it; time is the saved `day` counter that moves only on the `review_day` action ("Let a day pass"), never a wall clock. A question is a pure function of (set, version, item, times asked); pinned by `tests/fixtures/review_questions_v1.json`.
- `achievements.py` + `achievements.json`: 27 achievements computed from state, none hidden or luck-gated (7 for the cause web and myth or record: First Thread, Clean Web, Whole Web, First Sort, Myth Spotter, Straight Sort, Fair Judge; 8 for milestones 6 and 7: First Source Weighed, Primary and Secondary, Careful Reader, Every Account, In Their Shoes, Every Crossroads, First Recall, Long Memory).
- `report.py`: the report payload builder.
- `settings.js`: per-device display settings (`chronicle-text-scale`, `-reduced-motion` (starts from the system setting), `-effects`, `-high-contrast`), never in the save.
- `review.html`: the owner's spot-check page, direct URL only (noindex): every claim with its sources, confidence and a re-check of the source rule, plus every account passage (author, date, kind, what it mentions and leaves out, its source link) and every decision point (options, what was chosen, claim ids). Gives away every answer.

## The set format (a folder under `sets/<id>/`, listed in `sets/index.json`)
`meta.json` (id, title, status `sample-draft` | `draft` | `reviewed`, version, nuance_window_years), `sources.json` (registry), `entities.json` (events with `date` or `start`+`end`, `seq`, `section`, `place`, `people`; kind `event` or `context` = "elsewhere"; plus `people` and `places`, each with `match` text its claim must contain), `claims.json` (subject, field, value, text, confidence `documented` | `disputed` | `traditional-but-doubtful`, `alternatives` required for the last two, `sources: [{source, note}]`), `relations.json` (cause links `{id, from, to, type: led_to, strength: direct | contributing, claim}`; each relation has its OWN claim with `field: "relation"`, `value: "<from>><to>"` and the EFFECT as `subject`, so it has the usual 3+ sources and a confidence; several causes of one effect are fine; violations are `E_RELATION_CLAIM`, `E_RELATION_ORDER`, `E_RELATION_CONTRADICTION`), `chapters.json` (OPTIONAL: `{"web": [{id, title, blurb, size 3 to 6, events}], "myth": [{id, title, blurb, size, claims}]}`; a web chapter unlocks when every event in it is learned and its relations are those with both ends inside; a myth chapter lists claims about events (each with a `short` name) and unlocks when their events are learned; `E_CHAPTER*` codes: every relation must be in a web chapter, every disputed or doubtful claim in a myth chapter, a myth chapter needs both kinds of claim; a set without it simply has neither mechanic), `accounts.json` (OPTIONAL, whose account?: `{"accounts": [{id, event, title, blurb, points: [{id, label, claim}], passages: [{id, source, text, author_id, author, written, kind, vantage, purpose, purpose_note, mentions}]}]}`; a point is a DOCUMENTED claim about the account's event with field `account` and value `<account>:<point>` (so it has its own three sources); a passage is a 80 to 520 character ORIGINAL summary of ONE real source in sources.json (no quotation marks), `kind` primary | secondary, `written` the date it was written (required for primary; secondary web pages may be null = "undated web page, read on <date>"), `vantage` took-part | watched | later (primary = took part or watched, secondary = later), `purpose` announce | commemorate | personal-note | explain | persuade, `mentions` the points the passage covers (the rest are what it "leaves out", judged against the summary, never the whole source); codes `E_ACCOUNT*`: 2 to 4 passages, one primary and one secondary, different authors, 3 to 8 points, at least one omission, at least 4 authors across the set), `decisions.json` (OPTIONAL: `{"decisions": [{id, event, who, when, title, question, options: [{id, text}] (2 to 4), chosen, claims: {options, choice, after}}]}`; each of the three parts is a DOCUMENTED claim with field `decision` and value `<decision>:options|choice|after` and its own three sources, and the options claim must not reveal the choice; codes `E_DECISION*`), `sections.json` (unlock order via `requires`, difficulty 1 to 3, puzzle `size`, `min_gap_years`, `clear` = learn_all or solves n, or `from_sections` for a mixed section), `readings.json` (short, cite claims). Dates are ISO (`1789-04-30`, `1789`, BCE as `-0431`). Event ids carry no year (an id must never give the answer away). Adding a set is adding a folder and a line in `sets/index.json`.

## How the game plays (milestones 2 and 3)
Pick up a card, put it in a slot (tap, drag, or number keys). Check when full: right cards lock and are LEARNED (added to the archive), wrong ones say earlier or later. Solved: the reveal shows each date, its claim, a confidence badge (symbol + words + border style) and three linked sources, plus the nuance strip (an SVG scale of years with the puzzle's moments as circles and elsewhere events as lettered diamonds; every elsewhere event inside the window is learned too). Show the answer reveals but learns nothing. Sections unlock in order and are cleared when every event is learned (the mixed last section: solve 3). Clearing a section opens its reading. The archive counts moments, elsewhere events, people and places (people and places are found through their moments); percent is 100 only when everything is found, which a test proves reachable.

## The cause web (milestone 4) and myth or record (milestone 5)
A mode tab row (Timeline, Cause web, Myth or record; keys T, W, M) switches the board; the chapter cards under it list that mode's chapters. **Cause web:** the board lists the puzzle's moments earliest first (numbered, with an SVG of arcs over a line). Pick the cause, then the effect: the engine answers confirmed (the relation exists: its strength, confidence, `plural_note` and three sources show at once), reversed or "not confirmed" (it never says the moments are unrelated). Unlimited tries, each unconfirmed thread counts as a miss (`Clean Web` = a solved puzzle with 0 misses). Strength is written ("Direct cause" ⇒ / "Contributing cause" ⇢), bordered (solid thick / dashed) and drawn (solid thick / dashed arc). `plural_note` says "One of N causes of this moment that the set records", or, when there is only one in the set, that the sources name others that are not cards here. **Myth or record:** each statement gets one of three bins (documented / disputed / traditional but doubtful) by button or keys 1 to 3; Check locks the right ones (they join the archive) and never names the right bin for a wrong one; when all are right (or Show the answer, which learns nothing) each claim shows its label, alternatives, three sources and a "Why" built from its own source notes. A puzzle view never contains `confidence`, sources or the answer before it is finished (tests). **Meter and achievements:** the archive meter total is moments + people + places + reachable relations + reachable myth claims; archive groups "Connections" and "Records and myths" open to the claim and its sources.

## Whose account? (milestone 6), decision points and review (milestone 7)
Six mode tabs now (Timeline, Cause web, Myth or record, Whose account?, Decision points, Review; keys T, W, M, A, D, R). **Whose account?:** the board shows every passage of one account (a short original summary of a real source each, never quoting) with the focus passage marked by a diamond and a double border; the player answers fixed-option questions; Check locks the right ones (never naming the right answer for a wrong one); all right = that passage's source is JUDGED (archive group "Sources weighed", meter +1) and the reveal shows each passage's author, date (or "undated web page, read on ..."), kind, what the writer could see, purpose with a "Why we say so" note from the source, the source link with its read date, what it mentions and leaves out, and the account's point claims with three sources each. A board view never contains the author, source, kind, mentions or the answer before it is finished (tests). **Decision points:** the situation (the options claim, with its sources) and the options are shown; the player picks (once; a first choice is never replaced) and the game then shows "What <who> chose" and "What followed", each a sourced claim, plus the note that there is no right answer and that it does not claim to know what would have happened otherwise. Archive group "Crossroads", meter +1 per choice made. **Review:** one ready question at a time (the earliest due, then new facts in fixed order); an answer shows the sources and says when the fact comes back ("tomorrow", "in 3 days"); a wrong answer is gentle ("comes back tomorrow, and nothing is taken away"); "Let a day pass" is the only thing that moves time; counts are written in words (ready now, coming back later, at the longest gap). Review never changes the archive or any other progress (a test compares state). No streak, overdue, missed, penalty or countdown wording anywhere (tests scan the files).

## Progress and save
`get_state()`: `{schema: 3, sets: {id: {learned, solved: {"s1:0": {checks}}, revealed, threads, sorted, web_solved: {"w1:0": {misses}}, myth_solved: {"m1:0": {checks}}, judged: ["a-gettysburg/p1"], account_solved: {"a-gettysburg:0": {checks}}, decided: {"d-sumter": {picked}}, srs: {"ev:e-kennedy": {step, due, last, asked, right}}}}, day, viewed, settings {set, hints, mode}, flags, session, web_session, myth_session, account_session, decision_session, achievements_earned}` (schema 2 saves and older lack the new fields and load fine; the day counter never runs backwards on a merge, a saved review record is kept one at a time and dropped if any number is out of range, a first decision is never replaced, a hostile account session is dropped; sessions and ids are validated one field at a time, a hostile session is dropped, a session's found links and locked claims must really have been earned). The session (current puzzle and placement) is saved so a reload resumes; a hostile session is dropped (tests). Progress for a set this build lacks is kept and written back. After `load_state` the engine calls `window.chronicleOnStateLoaded()`. `chronicle:state` in localStorage mirrors the last state; the save widget (`shared/save-widget.js`, `data-game-id="chronicle"`) POSTs to the live backend ONLY when the player presses Save, which this build never does by itself.
