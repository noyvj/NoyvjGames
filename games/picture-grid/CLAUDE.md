# Picture Grid (working title)

Seed: `planning/picture-grid-plan.md` (Quick ideas round A12, TODO QI-12). Personal project, no BCM tag. Milestones 1 to 7 built 2026-10-12 by background agents (the first complete game, the standard kit, achievements and the Desktop boot). NOT yet linked from the hub or registered anywhere (no `sw.js` precache, no `game-manifest.json`, no `offline-manifest.json`, no site-settings key): hub registration is the separate step QI-12-R.

## One-line pitch
Nonograms in a quiet gallery: fill each grid from the number clues on its rows and columns, and every solved picture is hung on a wall of space, robot and machine scenes that you can browse.

## Stack
- Pyodide Python, plain HTML/CSS, no build step. `game.py` is the single engine entry point (`handle(json) -> json`, `get_state()` / `load_state()` for the shared save widget); `app.js` is glue only (it draws SVG and turns input into requests). Python 3.9 locally (Pyodide 3.12): no 3.10+ syntax in engine code. No Node is available in this repo's tooling: check JS in the browser.
- Runs from any static server. No audio, no image files (every picture is a bitmap written out as data, drawn as SVG).

## Core constraints (do not violate without asking)
1. The engine is pure and deterministic: no clock, no randomness (a test scans every engine module). Clues are a pure function of the stored bitmap.
2. Nothing is timed, nothing can fail, nothing is lost. Marks are free to clear, undo and redo. A hung picture stays hung.
3. No luck and no guessing: every picture is PROVED to have exactly one solution AND to be solvable by line logic alone (see below). A picture that fails is redrawn, never shipped.
4. Never colour alone: a filled cell is a block with a facet and a hatch, a dot is a round mark, a wrong cell (Check mistakes) is a dashed outline with a slash, a finished clue greys and gets a tick, the selected tool has a thicker border, the keyboard cursor is a heavy ring. Everything visual has a text version (cursor line, "Clues as text", "Describe this picture in words").
5. Effects toggleable (the glow when a picture is hung); reduced motion honoured; light and dark theme; high contrast; text size.
6. All pictures are small pixel bitmaps authored by hand as data. No generated or downloaded images.

## How correctness is PROVED (`nonogram.py`, `tools/check_pictures.py`, `tests/test_pictures.py`)
- `solve_lines(rows, cols)`: the line-logic solver. One row or column at a time, it keeps every cell that is filled (or empty) in every arrangement of that line that fits the clue and the cells known, and repeats to a fixpoint. No branching, no guessing. `line_deductions(clue, cells)` is the per-line step (milestone 4's hint ladder will use it, so hints are always logically justified).
- `count_solutions(rows, cols, limit)`: the exhaustive counter (line logic, then branch on an unknown cell, so every picture that fits is visited). `count_by_rows`: a second counter that shares no code with the solver (every row arrangement, pruned only by column prefixes); the tests cross-check the two.
- Every picture: exactly one solution (both counters), finished by line logic alone and equal to its bitmap, clues match the bitmap row by row and column by column, deterministic. `python3 tools/check_pictures.py [gallery-id] [--draw]` prints the proof table; `suggest_fixes(rows)` lists one- and two-cell edits of a draft that pass (symmetric drawings are usually ambiguous and need one asymmetric pixel).

## Content
`pictures_g1.py` Instruments (10 pictures, 5x5), `pictures_g2.py` Small Machines (10, 8x8), `pictures_g3.py` Robots (10, 10x10), `pictures_g4.py` Station Rooms (10: five 10x10, five 12x12), `pictures_g5.py` Deep Sky (five 12x12, five 15x15), `pictures_g6.py` The Long Wall (three 12x12, seven 15x15; the last picture is "The Long Gallery", a frame with a small sky inside): 60 frozen pictures (id, title, one-line caption, tint, bitmap). Galleries 4 to 6 were drawn as rough ASCII, run through `tools/check_pictures.py`, and the few that needed it got a one- or two-cell edit from `suggest_fixes()`-style search (the airlock, locker and toolbox, for example, passed first time; crescent, comet, capsule, clock, moth and long_gallery were edited). Every picture is proved: exactly one solution (both counters) and finished by line logic alone (`python3 tools/check_pictures.py` takes about 3 s for all 60). Duplicate ids/titles are avoided (there is one Key, one Lantern, one Compass, one Rocket, one Flask, in the first two galleries only). `pictures.py` wraps them (`GALLERIES`, `ALL`, `BY_ID`, `ORDER`), derives the clues and holds the gating. Tints (`brass teal rose violet moss sky`) are three-tone ramps in `style.css` (dark and light); a hung picture is drawn with the ramp's tones banded by row thirds.
Adding a gallery: write `pictures_gN.py`, add it to `pictures._MODULES` and to `ENGINE_MODULES` in `app.js` (a test checks the list), run `tools/check_pictures.py`, then the tests.

## Gating
Gallery 0 is open from the start; gallery n+1 opens when `OPEN_AT` (6) pictures of gallery n are hung (any six); inside a gallery every frame is open in any order. Derived from the hung set, so it only ever goes up. A save is judged in gallery order on load, so a hand-edited save cannot skip ahead.

## Engine and page notes
- `game.handle` returns the whole view. Actions: `open`, `pick {picture}`, `next` (next open frame not yet hung), `paint {cells: [[r, c], ...], value 1|2|0}` (fill / dot / unknown; one call = one undo step and one "stroke"), `undo`, `redo`, `assist {name, on}` (`check`, `autodot`, `focus`: all off by default), `retry` (solve a hung picture again from a blank frame; it stays hung; fewer strokes improves its best), `reset`.
- A frame is finished when every row and column's FILLED cells make exactly its clue (dots and unknowns both count as empty); the engine then hangs it, keeps the best stroke count and shows the picture clean (filled cells only, tinted). A hung frame is read-only until Solve it again. The view never contains an unhung picture's title, caption or bitmap (a test checks).
- The tally counts the player's own marks only (fills, dots, clears); auto-dots are free and not counted. "Cells filled" is the headline stat; "Strokes here" counts this frame's strokes.
- Save (`get_state`, only non-default keys besides `schema`): `cur`, `solved {id: best strokes}`, `work {id: rows of ".#x"}` (an unhung frame with any mark, or a hung picture being solved again), `moves {id: strokes}` (only for saved frames), `tally`, `assist`, `hints {id: highest rung}`, `slides`, `achievements_earned` (write-only, never read back). Undo history is not saved. `load` checks every field alone, drops pictures in closed galleries and frames of the wrong shape or alphabet, and hangs a saved frame that is already complete. A `schema` key (1) is always written; a save with a missing schema is read as layout 1, one with a bad or newer schema is ignored (a fresh game), and every other key is optional so old saves stay compatible.
- Page: the SVG board is drawn by `app.js` (`drawBoard`): clues left and above with a tick when the engine says a line is satisfied, marks, grid lines (heavier every fifth), a heavy keyboard ring. Input: pointer drag along a line (the first move locks the row or column; a stroke started on an empty cell fills or dots only empty cells, one started on a mark clears marks of that kind), right button / Shift / Alt dots, Fill/Dot buttons for touch, keyboard (arrows, Space/Enter marks, F/X choose tool, Backspace clears, Shift+arrow marks the cell moved onto, Ctrl/Cmd+Z undo, Ctrl/Cmd+Shift+Z or Y redo). Cells fit the width down to 24 px; Settings "Large cells" makes them 44 px and the board scrolls sideways (a quick tap still marks on a scrolling board).
- Engine modules (loaded in this order by `app.js`): nonogram, pictures_g1..g6, pictures, hints, goals, achievements, info, then game. A test checks the list.
- Gallery wall (`#gallery-panel`): each gallery with hung/total, locked galleries say how many more to hang; a hung frame is a small tinted picture with name, size and strokes (opens the large view: big picture, caption, a words description, previous/next hung, Solve it again); an unhung frame is a dark frame you can open to play.
- Board layout (milestone 4): cell size is chosen in screen pixels (44 down to 15; clue numbers keep a floor of 11 px so they stay readable) and converted to drawing units, so a 15x15 fits a 360 px phone without sideways scrolling for most pictures (the five-number ones, observatory and moth, scroll a little) and a 44 px board at 1440. "Large cells" in Settings still forces 44 px and scrolls. Checked live at 360x740 and 1440x900 on the 15x15 "The Long Gallery".

## Hint ladder (`hints.py`, milestone 4)
- Every rung opens only on a press of the suggestion button ("Would you like a suggestion?"; the owner's wording). `hint {confirm}` in `game.py`; the view carries `hint` (only the rungs pressed so far; never the cells before rung 3) and `hint_ui` (what the button offers next, its label, whether a confirm is needed, the Hard limit).
- 1 nudge: "Row 4 has a move that is certain" (no cell). 2 hint: the line, its clue and the KIND of reasoning (`empty`, `complete`, `exact` fit with no spare room, `overlap`, `pinned` by marked cells), still no cell. 3 fill: the certain cells of that line are put on the frame (one undo step, filled cells and dots, not counted as the player's own fills; the page asks a confirm on Normal).
- The line comes from `nonogram.line_deductions` on the player's CORRECT marks only (a wrong mark is ignored, never named, and a fill replaces it): most certain fills, then most moves, rows before columns, lowest first, so a hint is always logically justified and deterministic; a test presses through the ladder alone on every sixth picture and checks no wrong cell is ever placed and the picture always finishes.
- Counting: `tally.hints` counts every press that opened something (Easy's first press counts once); `hints {picture: highest rung}` records the highest rung asked while a picture was first being solved (a hung picture being solved again still counts presses but leaves the record alone), saved as `hints`; the large view says "(with a suggestion)" or "(no suggestions)". Milestone 6's "Clean Lines" reads `hinted`.
- The line a suggestion points at gets a dashed outline on the board (never colour alone), only after a rung is open. Settings can hide the whole suggestion box (`picture-grid:hints-hidden`).

## Difficulty (AN-17, shared/difficulty.js)
`NoyvjDifficulty.mount("#difficulty-slot", ...)`, remembered per browser in `difficulty:picture-grid`, told to the engine with `{action: "difficulty", level}` (a module global that `reset` and `load` leave alone, never saved). Easy: the first press opens the nudge and the hint together and the fill needs no confirm. Normal: as designed. Hard: no fill step (the nudge and hint are all there is). The level changes only how the ladder opens, never the pictures, clues, rules or any record (a test runs one scripted session on all three and requires identical hung set, cells, best strokes and goals; another requires Normal told equals never told). A change of level clears a ladder opened under the old one.

## Goals strip and slideshow (milestone 4)
- `goals.py` builds the ordered queue (the shared `goals-panel.js` shows the first three not done): the next gallery to open ("Hang 6 pictures in Instruments", reward "Opens Small Machines"), the next cell milestone (100, 500, 1,000, 2,500, 5,000, 10,000), "Hang all 10 pictures in <gallery>", and the hung-total milestones (10, 30, 60). Not-done goals come first in that rotation, done ones after (so the panel can announce a completion), all numbers only go up. A Settings checkbox hides the strip. Stats strip: Pictures hung, Cells filled, Galleries done, Hints asked, Strokes here.
- Slideshow: a button in the Gallery panel opens the large view in slideshow mode over the hung pictures (left and right arrows step, Escape closes, nothing moves by itself and there is no timer). `slideshow` sets a saved flag (`slides: 1`, view `slideshow_seen`) for milestone 6's "Slow Light".

## Achievements (milestone 6: `achievements.py`, `achievements.json`)
- 14, the hub-wide pattern (Rule Finder / Hull Repair are the siblings): `achievements.json` is the static manifest (id, label, description), `achievements.py` holds the same table as `(id, label, description, fact, need)` plus pure functions `facts_of(solved, hinted, fills, slides)`, `earned(facts)` and `view(facts)`; a test keeps the two in step. Everything is derived from saved inputs that already round-trip, so a loaded save and a played one cannot disagree. `get_state()` writes `achievements_earned` (only when not empty), a write-only projection that `load` never reads back; the view carries `achievements` (id, label, description, earned, have, need).
- The list: First Frame (1 hung), Ten Hung, Thirty Hung, Sixty Hung (every picture), Small Hands / Machine Shop / Robot Row / Station Rooms / Deep Sky Done / The Long Wall (every picture in that gallery), Big One (a 15 by 15 hung), Clean Lines (10 hung pictures with no suggestion: `hinted` has no record for them), Slow Light (the Slideshow was opened: `slides`), Ten Thousand (10,000 fills: `tally.fills`, the player's own fills only; dots, clears and the ladder's fill do not count).
- Never gated: no achievement reads the difficulty (a test scripts the whole game on None/Easy/Normal/Hard and requires the same earned set and numbers; another scans `achievements.py` for the level), none is hidden, timed or luck-based, and each shows `have of need`. Reachability: a scripted player on Normal with no hint earns all 14 (test).
- Page: toolbar button (Achievements, short label "Trophies 3/14"), `#achievements-panel` with `#achievements-count` ("N of 14 achievements earned."), a list whose rows carry `data-achievement-id` and a `.tick` ("Earned" or "3 of 10": the earned state is a word and a double border, never colour alone), the shared Share button (`achievement-share.js`), and a toast plus announcement once for each one newly earned (`knownEarned` is null until the first view and is reset when a save is loaded, so loading never fires a toast). The unlock text is appended to the hung-picture toast.

## Desktop boot (milestone 7: `pc-config.json`, `pc.css`, `pc.js`, generated `pc.html`)
- `pc.html` is GENERATED from `index.html` + `pc-config.json` by `scripts/generate-pc-pages.py` (never edit it by hand; a test compares it with `build("picture-grid", cfg)`). Same engine, same `game_id`, so the save is shared with Classic; `index.html` gained only the `layout-pref.js` include and the `pictureGridTutorialSteps` hook.
- Layout (1440x900): top bar = back link, title, the five stats, then the icon buttons (Gallery, Achievements, Settings) and the Menu (Tutorial, About, Credits, Report, What's New, Fullscreen, Classic layout); the STAGE is the frame (a one-line title and caption, the board filling all the remaining height, the cursor line); a right-hand column (scrolls inside itself) holds the three goals, Prev/Next, the Fill/Dot/Undo/Redo/Clear tools, the suggestion ladder, the hung card, "Clues as text" and the Difficulty chooser. Windows: The Long Gallery (wall, large view, Slideshow), Achievements, What's New, Settings, About. The hotkey bar lists the game's own keys.
- The board sizes itself to the stage: `layout()` in `app.js` also fits the HEIGHT when `data-layout="pc"` (and cells may grow to 72 px there for the small pictures); Classic is unchanged (no height limit). A 15x15 gets about 37 px cells at 1440x900 with no scrolling; "Large cells" still forces 44 px and the board wrap scrolls.
- `pc.js` defines `PICTURE_GRID_PC_TUTORIAL_STEPS` (eight steps, every selector an id that exists on `pc.html` or a shell id); `app.js` runs them instead of the Classic seven through `pictureGridTutorialSteps`.
- Known limits: the Difficulty chooser is tall when open, so the side column scrolls on a short window; below about 1000 px wide the Classic layout is the better one (layout-pref picks it).
