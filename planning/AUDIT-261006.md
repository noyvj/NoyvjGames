# Playtest audit — 2026-10-06

A find-only playtest pass over the hub and all 13 games. Method: a fresh-profile load of every
page (console, network, accessibility hygiene), screenshots of each game at desktop (1440x900)
and phone width (390x844, real device-metrics emulation, not a narrowed window) both at first
load and after some play, random-click ("monkey") sessions, and state-invariant checks through
`get_state()`. Nothing here has been fixed yet; this is evidence, not a task list. Fold anything
worth doing into `planning/TODO.md`.

What was **not** covered: a full start-to-finish playthrough of any game, real touch input
(clicks only), screen-reader behaviour, and the signed-in account flows (to avoid writing to the
live database). Findings from the screenshots are "seen"; findings marked **confirmed** were also
reproduced with a DOM query on the local dev server.

Severity: **P1** a player will hit it and it gets in the way, **P2** annoying or confusing,
**P3** cosmetic.

## Clean results

- **No JavaScript errors or failed requests on any page** (hub + 13 games), apart from the AdSense 400 (S6).
- No broken images, no duplicate ids, no unnamed buttons/links/inputs, no horizontal page overflow at 390px on any game page.
- The earlier backend outage is fixed; ratings, stats and leaderboards respond.

## Findings

### S1 — Save/Load widget covers game UI on phones (P1)
`shared/save-widget.js` is `position: fixed` bottom-right and starts expanded (about 200x230px).
At 390px wide it sits over the right half of the lower screen in every game. Seen covering:
Aftermath's "Face the…" primary button, Signal's "Commit answer", Tide's "Advance", Grid's
"Advance", Canopy's action row, Drift's story text, Champ de Mots' sentence tiles. It can be
collapsed with the small triangle, but a first-time player has no reason to. Expected: collapsed
by default below ~600px wide (or a small floating icon).

### S2 — `hidden` attribute defeated by CSS `display` (P1/P2)
Confirmed live with `[hidden]` + visible-rect queries:
- **Continuum:** `div#achievements-panel[hidden]` renders as an empty rounded bar above "Benchmark your city" on first load.
- **Aftermath:** `label#extended-run-toggle-wrapper[hidden]` (the "Extended Run" checkbox) shows from the start, but `game.py:2392` only intends it once the run is complete.
- **Drift:** `p#net-positive-badge[hidden]` and `p#recovery-badge[hidden]` render as two empty 20x8px bordered pills (`.net-positive-badge { display:inline-block }`).
- **SOL:** `#prestige-badge` and `.cross-summary { display: grid }` (seen, from earlier pass).
- **Hub:** `#whats-new-badge[hidden]` vs `.nav-badge`: a stray blue bar after "What's New" in the nav on first load.
- **Canopy:** the `#undo-clear-button` (seen visible with nothing to undo).

Single root-cause fix: a shared `[hidden] { display: none !important; }` in each game's base
stylesheet (and the hub's `style.css`). Cheap, and it also prevents the next one.

### S3 — Opening screen rows squash at 390px (P2)
`shared/opening-screen.js` (~line 104): `.opening-row { display:flex; gap:.5rem } .opening-row > * { flex:1 1 0 }`
has no `min-width:0` or wrap, so long labels squash or push beyond the card on narrow screens. Fix: `flex-wrap: wrap` plus `min-width: 0`.

### S4 — Canopy phone layout (P2)
`.action-buttons` is a no-wrap row holding Clear / Replant / Adopt plot / Tend / Undo clear; at 390px
the last button wraps text into three lines ("Undo / clear") and the row presses against the save
widget. `#specialist-row` ("Specialize: economic") is clipped at the right edge. Several panels
(Stats & Legend, Plot details, Harvested income) draw over each other in the played screenshot.

### S5 — Toasts on mobile (P2)
Achievement toasts sit centred near the top and cover the "Canopy" heading and the back link (Canopy,
SOL). In Trade Empire the toast appears bottom-centre and is partly hidden behind the save widget
and the bottom-left toggles, so its text is unreadable ("Achiev… Whatever's…").

### S6 — AdSense 400 (P3)
Every page logs an HTTP 400 from the AdSense script, as expected while the placeholder client ID
(`ca-pub-XXXXXXXXXXXXXXXX`) is in place (FOR-YOU item 1). Harmless, but it is the only network error
site-wide and will make real errors harder to spot. Consider not loading the script until a real ID exists.

### S7 — First visit stacks two overlays on the hub (P2)
A fresh profile gets the Install banner and the onboarding survey at the same time, on top of the
hub tour waiting behind them. On mobile the combination fills the screen before any game is visible.

### S8 — Floating toggles on mobile (P2)
"Light mode" and "Story: on/off" are fixed bottom-left pills. At 390px they sit over game text in Tide,
Thaw, Drift, Loop, Aftermath, Herd (e.g. Thaw's chart caption, Drift's changelog entries). With the
save widget (S1) about a third of the lower screen is chrome. Suggest moving both into Settings on narrow screens.

### S9 — Champ de Mots Day 1 (P3, design question)
A brand-new profile shows "790 plots are ready for water today." This follows from milestone 34
(removing the row-unlock gate), so it is not a bug, but the number reads as an unbeatable to-do list
on first contact. Consider capping the headline to today's actual session size.

### S10 — Continuum phone start screen (P3)
The Pause / 1x speed bar overlays the bottom of the Starting Scenario card (it covers "Hard Mode: OFF")
until the player scrolls.

### S11 — Smaller items (P3)
- Loop's "closed the loop" banner covers the top row of buttons (Tutorial / How to Play) until it dismisses.
- Loop's "← All games" link and the "Loop" heading share one line and nearly touch on phone.
- Save widget header is a 164x17px tap target (smallest on the page); Loop's `regional-hint-dismiss-button` is 52x21px.
- A "Saved!" status can remain after later changes, so it reads as current when it is not (seen earlier).
- Failed load shows a generic error without hinting at the usual cause (wrong code format / offline).
- Herd in light theme: first tutorial step overlays the whole page; worth a re-check of contrast on the dimmed layer (seen only, not measured).

## Test data I wrote to production (disclosure)

Before I added a write-blocker, my random-click sessions pressed a few real buttons on the live
site. Result: some in-game feedback rows (response `yes`/`no`, no stars) in the `ratings` table, and
a handful of anonymous rows in `saves`. They are included in the public per-game counts, so they
slightly inflate them. The API has no delete route, so cleanup needs the Neon SQL editor. Review
before running:

```sql
-- preview first
SELECT game_slug, response, count(*) FROM ratings
 WHERE stars IS NULL AND response IN ('yes','no') AND created_at >= '2026-10-05'
 GROUP BY 1,2 ORDER BY 1;
SELECT id, game_id, created_at FROM saves
 WHERE user_id IS NULL AND created_at >= '2026-10-05' ORDER BY created_at;

-- then, only if the preview matches what you expect (your own testing may be mixed in)
DELETE FROM ratings WHERE stars IS NULL AND response IN ('yes','no') AND created_at >= '2026-10-05';
DELETE FROM saves   WHERE user_id IS NULL AND created_at >= '2026-10-05';
```

The date filter may also catch genuine submissions from 5 Oct onward, so check the preview first.
