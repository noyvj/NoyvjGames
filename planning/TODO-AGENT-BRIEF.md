# Brief for TODO batch agents (one agent per game)

Used by the main session to hand a game's section of `planning/TODO.md` to a background agent. Copy the body into the Agent prompt and fill in the game.

## Prompt body

You are implementing items from `planning/TODO.md` for ONE game, working in /Users/alexhart/BCM Project folder/bcm206. You own ONLY files inside `games/<slug>/` (index.html, style.css, game.py and engine modules, tests, pc-config.json / pc.css / pc.js, CLAUDE.md, changelog.json). Do NOT edit `planning/` (including TODO.md), `shared/`, `sw.js`, other games, root files, dev logs, and run no git commands; the main session ticks TODO items and commits. Read `games/<slug>/CLAUDE.md` first, then the game's section of `planning/TODO.md` (find it by the game's name; items look like `- [ ] X-12: ...`) and the standing decisions at the top of that file (no roguelike or deck mechanics, easy to 100%, effects toggleable, collector ideas welcome, audio is parked, real-world facts read live and named on screen, every minigame action must count toward a visible stat).

Pick the items you can finish well WITHOUT the user's input: skip any item that needs a decision from the user, depends on an unbuilt shared component (W-1 level select, W-3 skill tree, W-4 seasonal groundwork, W-5 leaderboards, multiplayer), needs new art assets that cannot be drawn by code (never use generated images), or needs a backend change. List every skipped item with the reason in your report so the main session can move questions to FOR-YOU. Aim for roughly 5 to 8 solid items (quality over count); finish each one fully: engine/rules, UI, tests, and keep the Desktop boot (`pc.html`, generated from `index.html` plus `pc-config.json`; regenerate only your own through a scratch script that imports `scripts/generate-pc-pages.py` and calls `build("<slug>", cfg)`) working: every new element id the game code uses must exist in both pages, new panels/buttons must be reachable in the Desktop Menu or windows (the generic test `shared/tests/test_pc_games.py` fails otherwise: run `python3 -m pytest -q shared/tests`). All existing tests of the game must keep passing; add tests for every new rule. Add a short player-facing entry to `changelog.json` (raise the entry cap in the test only if needed) and update `CLAUDE.md`.

Verify live in the browser using your OWN tab (open it with tabs_create and pass your tabId to EVERY browser call; if tabs_create fails with a tab cap error use a headless Chrome via Playwright against http://localhost:8073). `hub-dev-server` runs on port 8073 (start with preview_start name hub-dev-server if needed); Pyodide needs ~10 s; the opening screen appears first (`#opening-screen [data-action=new]` then `[data-action=tutorial-no]`). Check both `index.html` and `pc.html` at 1440x900 and 360x740 (Classic only at 360). Never submit feedback, ratings or saves to the live backend. Final report: items completed (by id), items skipped (id and reason), files changed, test counts before and after, what you verified live, what you could not.
