# Lexis (working title): a language-deduction puzzle game, groundwork plan

Status: PLAN ONLY. No `games/lexis/` folder exists. Written 2026-10-06 after the user asked "can we build a puzzle game like The Message from Deep Space or Chants of Sennaar?". Once the questions in section 9 are answered this becomes the seed for `games/lexis/CLAUDE.md` (per `game-template.md`).

A note on references: Chants of Sennaar is known to me (you learn several invented languages by watching how their glyphs are used around you and filling in a notebook of guesses). I do not reliably know "The Message from Deep Space", so I am assuming it is about decoding an alien message by deduction. If it is something different, the answer to question 1 below matters more than anything else in this plan.

## 1. One-line pitch
You arrive somewhere nobody will explain; learn each local language by watching what its signs are used for, then use it to get things done.

## 2. Why it fits this site
- **Stack fit.** The core is a small, deterministic rules engine (a made-up grammar, a lexicon, a world that reacts), which is exactly the pure-Python-engine-plus-thin-view shape of Signal (190 tests) and Continuum. Pyodide runs it unchanged; no new dependencies.
- **Taste fit.** No roguelike or deck mechanics. Upgrades are knowledge, not luck. It is completionist by nature (a glossary that fills in), and every puzzle is deterministic so the game can be easy to 100%. Effects (glyph pulses, shakes) get off switches.
- **AI-ethics boundary.** The glyph art is generated by code from a stroke grammar (SVG), not by an image model, so the project's "no generated images" line holds.
- **Site fit.** Uses the shared save widget, achievements framework, tutorial, Info page ("real linguistics behind this": word order, plural marking, numeral systems), opening screen and, later, the Desktop boot.
- **Relationship to Le Champ de Mots.** That game drills real French; this one teaches the skill underneath it (noticing structure), with invented languages so there is nothing to memorise and nothing copyrighted.

## 3. The core loop
1. **Observe.** A scene shows people, objects and signs. Signs appear next to the things they mean, in situations that make the meaning guessable (a sign over a door, a speech bubble while someone hands over three loaves).
2. **Guess.** The player writes meanings into a notebook: tap a glyph, choose or type a gloss ("bread", "three", "give"). Guesses are free and can be wrong.
3. **Test.** Two ways to check a guess: a *dialogue* (build a sentence from glyph tiles, say it, and the world reacts correctly only if you were right) and a *confirmation puzzle* (match signs to pictures; the game says which of N are right without saying which words were wrong).
4. **Progress.** Correct understanding opens something: a door, a trade, the next district with a new language that shares some roots with the last.

## 4. What makes the puzzles good (and fair)
- **Every word must be deducible from earlier evidence.** A build-time checker (a test) takes a language definition plus the scenes and proves each gloss is the only one consistent with the evidence shown so far. If a word is ambiguous, the test fails and the scene gets an extra clue. This is the main quality guarantee and the reason to do this in Python.
- **Layers of difficulty, one new idea at a time:** nouns, then quantities and number words, then verbs, then word order, then plural and negation markers, then questions, then a language whose number system is not base 10, then a language that borrows from the earlier two.
- **Hints are in the world, not a hint button:** an optional "ask someone" action that makes a character repeat a sentence slowly, never telling the answer.
- **Deterministic parser and responder.** The conlang has a real grammar (a few rules per language); a sentence either parses to a meaning the world can act on, or the world visibly does not understand and says why in-world.

## 6. Architecture sketch
- `lang.py`: language definitions as data (lexicon, glyph strokes, grammar rules). `parse.py`: sentence to meaning. `world.py`: what an utterance does. `scenes.py`: evidence scenes. `notebook.py`: the player's glosses, validated against nothing (guesses are free) but scored for the glossary. `deduce.py` (tests only): the deducibility checker.
- `glyphs.py`: deterministic stroke grammar to SVG path data, so every sign is drawn by code, consistent within a language and visibly related across languages that share roots.
- Thin view: scene, notebook, sentence builder. Save = notebook plus progress (small JSON); no random state.
- Same conventions as Signal: static shell first paint, engine loaded after, tests with the fake-DOM harness, hub registration by the log owner.

## 8. Risks
- **Authoring cost** is the real cost: each language is designed content, not code. The deducibility checker makes this safe but not fast.
- **Fairness.** The most common failure of this genre is a word that cannot be deduced. The checker exists to prevent it.
- **Pyodide first load** is a few seconds; use the Signal pattern (static shell, instant first paint, engine after).
- **Originality.** Use no real language's vocabulary and nothing from either reference game's content; the mechanic (deduce meaning from context) is not ownable, the specific languages and art are ours.
