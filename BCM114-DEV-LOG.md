### 2026-09-02
**Game:** SOL, Canopy, Grid, Tide, Aftermath, Herd, Thaw, Drift, Loop
**Did:** Audited each game for bugs and dead/messy code, one parallel agent per game, as part of a full site-wide audit (root/shared/backend side logged in `BCM206-DEV-LOG.md`). Real bugs found and fixed: **SOL** — `deserialize_state()` used `.clear()` then `.update()` on the live planet-state dict, so a save file missing any single planet key (e.g. an older save predating a later-added planet) would delete that planet's state entirely and crash the very next `tick()` with a `KeyError`; fixed to an in-place per-key merge instead of a wholesale replace. **Grid** — `retire_plant()` refunded a flat fraction of the plant's *base* cost rather than its current (learning-curve-discounted) cost, so once a renewable's cumulative-built discount passed 50% off base, building then immediately retiring it returned more than it cost — a genuine risk-free money exploit; fixed to refund off the live cost. **Canopy** — a stakeholder relations request could keep referencing a plot that had already been cleared or preserved through some other path by the time the player responded, letting a stale request hand out a free relations bonus, wrongly penalize a already-resolved decision, or in the worst case permanently softlock the whole stakeholder-tension mechanic; added a liveness check plus an auto-dismiss for requests that go stale. **Aftermath** — the save widget can reload an older, still-valid save code written before a run's final event, even after that same run was already completed normally through ordinary play; replaying the final event from that stale save re-triggered the run-completion payout a second time, double-awarding skill-tree knowledge and duplicating the run-history entry. Fixed with a persisted per-run high-water mark that only pays out once per run number, deliberately kept outside the normal save round-trip (same pattern already used for the existing skill-tree/history exclusion). **Trade Empire** (not yet hub-linked, but audited anyway since a full pass is the right occasion) — all three Kepler-system colonies rendered the identical map label "Kepler," making them indistinguishable on the map; added a per-colony label override.
**Result:** 1,387 tests across these 9 games, all passing, zero regressions (each fix had a reproducing test added first). Tide and Loop were both audited and found genuinely clean — no bugs, no commit needed. Cleanup-only fixes (dead CSS/constants, stale comments, a missing CSS rule affecting 6 of 7 non-Earth "return to Earth" buttons on SOL) also landed across Herd, Thaw, Drift, and SOL — see each game's own git history for detail; not worth a full paragraph each here since none changed behavior.

### 2026-08-20 (continued)
**Game:** Continuum (working title) — new flagship BCM114 Round 2 DA
**Did:** Placed the full design doc at `games/continuum/CLAUDE.md` and built **Phase 1 (Foundation)** of it — the doc itself calls each phase "several sessions' worth of work, not one sitting," so Phases 2-4 (era-transition framework, six-era content expansion, polish/hub integration) are deliberately left for future sessions, same pacing discipline as every other game in this hub. Four milestones, built and tested in order: **M1 — core Tribal-era simulation** (`sim.py`): four worker roles (foragers/gatherers/crafters/keepers), four buildings, food production→consumption→spoilage, tool wear, population growth gated on surplus *and* housing headroom, starvation, and a land-health feedback loop where over-harvesting degrades future yield — deterministic, no RNG anywhere. **M2 — sustainability/livability score** (`sustainability.py`): four equally-weighted components (livability, equity, resource balance, resilience), every input a *ratio* never a raw count — the mechanism that actually delivers the design doc's core warning that a small careful settlement should outscore a large extractive one; tested directly (a careful settlement beats an extractive one by 30+ points; scaling a settlement up proportionally changes the score by exactly zero). **M3 — research tree engine** (`research.py`): a generic tiered engine (2 tiers/era × 7 eras = 14 tiers), soft tier-gating, three branches spanning all seven eras, and a `min_affinity` mechanism so early specialization opens branches a generalist can't reach later — nine Tribal-era nodes prove the system, and a `validate()` pass catches unknown/cyclic/late prerequisites and era/tier mismatches. **M4 — save schema**: built on the shared save widget (`shared/save-widget.js`, from the same-day infra session) rather than a bespoke bridge — the doc's own more complex need (revisit completed eras without losing forward progress) lives entirely *inside* the one dict the widget already treats as opaque (`{current_era, current_state, parked_state, era_snapshots, furthest_era, ...}`), so no second save system had to be built.
