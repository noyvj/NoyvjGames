**Game:** Canopy, Grid, Tide, Aftermath

### 2026-08-20
**Game:** Grid, Canopy, Tide, Aftermath, Herd, Thaw, Loop, Drift
**Did:** Merged and implemented a third external design-review pass (`climate-games-fun-teaching-balance.md`, saved to `planning/`) applying educational-game-design research to all 8 games: the "chocolate-covered-broccoli" risk (fun bolted onto a lesson rather than fused with it), Csikszentmihalyi/Chen flow theory (challenge should scale with the same mechanic that teaches the lesson, not a separate difficulty slider), and the Klim:S21 study's "trust, not just fear" finding (a game needs legible efficacy feedback, not just threat). Each game got its own risk/fix, run in parallel as 8 independent sessions since the work was fully self-contained per game directory. Grid: added a live status line stating in words that rising emissions drive disruption risk — the underlying math (`disruption_probability()`/`disruption_severity()` scaling off the emissions meter, capped not cliffed) was already correct from Milestone 3, the gap was purely legibility. Canopy: tightened the pacing of Pass 2's stakeholder-tension requests and biodiversity wildlife-icon payoff (20→15 ticks, and a payoff that previously didn't land until tick 50 now lands around tick 11) to close a long idle stretch between meaningful decisions. Tide: extended the Pass 1 ticker to narrate recovery and tier-unlock payoffs immediately, not just decline — a tier unlock now logs its dampening % the moment it's crossed, and the damage-trend flattening gets its own one-shot ticker message. Aftermath: made event-severity variation widen (symmetrically, not just upward) with skill-tree strength, so a fully-invested run still gets surprised rather than executing an already-solved strategy, while preserving the deterministic run-1-vs-latest comparison other tests depend on. Herd: audited whether `coupling_ratio()` actually drives the profitability number the player optimizes, rather than being a bolted-on side score — traced the code and confirmed it does, through two independent paths (a direct methane penalty and an income-pressure multiplier), and verified with real playthrough numbers (decoupled growth scoring 412 vs. pure growth's 52 by round 50) rather than trusting the docstrings; no code change needed, but the finding is now a permanent regression test. Thaw (flagged in the source doc as the highest-risk game on this axis): gave the preservation/monitoring intervention lever an immediate visible payoff — previously it silently raised a dampening percentage with zero perceptible effect until the melt threshold was later crossed, which is exactly the "fear without efficacy" failure mode the research warns about; added a green flash cue and an explicit "protection is in place now" readout, plus a second in-game feedback question asking directly whether the intervention felt like it worked. Loop: audited the Pass 2 single-item vignette and confirmed it already updates immediately and reflects the player's actual circularity/trade decisions (traced to the same live value the abstract chain view uses, refreshed synchronously on every state-mutating action) — already satisfied, now locked in with regression tests rather than left as an assumption. Drift: added a legible "turning point" moment (a persistent, non-flickering marker + institutional-framing callout) for the instant a region's integration mechanic crosses from net strain to net contribution, previously buried inside a background funds calculation, plus a second feedback question asking whether migration pressure came across as a manageable systems problem rather than an unmanageable crisis — kept deliberately institutional/systems-level per the game's existing sensitivity note, no individual-level dramatization.

### 2026-08-20 (continued)
**Game:** Continuum (working title) — new flagship BCM114 Round 2 DA
**Did:** Placed the full design doc at `games/continuum/CLAUDE.md` and built **Phase 1 (Foundation)** of it — the doc itself calls each phase "several sessions' worth of work, not one sitting," so Phases 2-4 (era-transition framework, six-era content expansion, polish/hub integration) are deliberately left for future sessions, same pacing discipline as every other game in this hub. Four milestones, built and tested in order: **M1 — core Tribal-era simulation** (`sim.py`): four worker roles (foragers/gatherers/crafters/keepers), four buildings, food production→consumption→spoilage, tool wear, population growth gated on surplus *and* housing headroom, starvation, and a land-health feedback loop where over-harvesting degrades future yield — deterministic, no RNG anywhere. **M2 — sustainability/livability score** (`sustainability.py`): four equally-weighted components (livability, equity, resource balance, resilience), every input a *ratio* never a raw count — the mechanism that actually delivers the design doc's core warning that a small careful settlement should outscore a large extractive one; tested directly (a careful settlement beats an extractive one by 30+ points; scaling a settlement up proportionally changes the score by exactly zero). **M3 — research tree engine** (`research.py`): a generic tiered engine (2 tiers/era × 7 eras = 14 tiers), soft tier-gating, three branches spanning all seven eras, and a `min_affinity` mechanism so early specialization opens branches a generalist can't reach later — nine Tribal-era nodes prove the system, and a `validate()` pass catches unknown/cyclic/late prerequisites and era/tier mismatches. **M4 — save schema**: built on the shared save widget (`shared/save-widget.js`, from the same-day infra session) rather than a bespoke bridge — the doc's own more complex need (revisit completed eras without losing forward progress) lives entirely *inside* the one dict the widget already treats as opaque (`{current_era, current_state, parked_state, era_snapshots, furthest_era, ...}`), so no second save system had to be built. One deliberate architecture exception, flagged in the doc's own tech notes and worth remembering: unlike every other game's single `game.py`, this one is split into `sim`/`sustainability`/`research`/`save` modules plus a thin `game.py`, with `index.html` writing each into Pyodide's virtual FS before running — still no build step, but this module-loading seam has no test coverage (re-check it live in-browser after touching that block).
**Result:** 92 tests across the four milestones, all passing, tagged `continuum-milestone-01` through `-04`. Verified live in a local browser: page boots, seasons advance, the research panel renders, the save widget appears and round-trips through Pyodide correctly. Not yet hub-linked (same status as Trade Empire) — hub integration is explicitly Phase 4 work. Several concrete decisions a future session should revisit rather than treat as settled: the era list (`sim.ERA_ORDER`) and the 2-tiers-per-era research structure are first-pass calls the doc explicitly asked to confirm before Phase 1 wrapped; balance numbers are untested guesses (a 2-forager settlement shrinks toward a small equilibrium in testing — real tension, never playtested); and `Campaign.advance_to_era()` exists and is tested but nothing calls it yet, since that's Phase 2's era-transition system to build.
