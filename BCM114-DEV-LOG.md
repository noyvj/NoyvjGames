### 2026-09-02
**Game:** SOL, Canopy, Grid, Tide, Aftermath, Herd, Thaw, Drift, Loop
**Did:** Audited each game for bugs and dead/messy code, one parallel agent per game, as part of a full site-wide audit (root/shared/backend side logged in `BCM206-DEV-LOG.md`). Real bugs found and fixed: **SOL** — `deserialize_state()` used `.clear()` then `.update()` on the live planet-state dict, so a save file missing any single planet key (e.g. an older save predating a later-added planet) would delete that planet's state entirely and crash the very next `tick()` with a `KeyError`; fixed to an in-place per-key merge instead of a wholesale replace. **Grid** — `retire_plant()` refunded a flat fraction of the plant's *base* cost rather than its current (learning-curve-discounted) cost, so once a renewable's cumulative-built discount passed 50% off base, building then immediately retiring it returned more than it cost — a genuine risk-free money exploit; fixed to refund off the live cost. **Canopy** — a stakeholder relations request could keep referencing a plot that had already been cleared or preserved through some other path by the time the player responded, letting a stale request hand out a free relations bonus, wrongly penalize a already-resolved decision, or in the worst case permanently softlock the whole stakeholder-tension mechanic; added a liveness check plus an auto-dismiss for requests that go stale. **Aftermath** — the save widget can reload an older, still-valid save code written before a run's final event, even after that same run was already completed normally through ordinary play; replaying the final event from that stale save re-triggered the run-completion payout a second time, double-awarding skill-tree knowledge and duplicating the run-history entry. Fixed with a persisted per-run high-water mark that only pays out once per run number, deliberately kept outside the normal save round-trip (same pattern already used for the existing skill-tree/history exclusion). **Trade Empire** (not yet hub-linked, but audited anyway since a full pass is the right occasion) — all three Kepler-system colonies rendered the identical map label "Kepler," making them indistinguishable on the map; added a per-colony label override.
**Result:** 1,387 tests across these 9 games, all passing, zero regressions (each fix had a reproducing test added first). Tide and Loop were both audited and found genuinely clean — no bugs, no commit needed. Cleanup-only fixes (dead CSS/constants, stale comments, a missing CSS rule affecting 6 of 7 non-Earth "return to Earth" buttons on SOL) also landed across Herd, Thaw, Drift, and SOL — see each game's own git history for detail; not worth a full paragraph each here since none changed behavior.

### 2026-09-02 (continued)
**Game:** SOL, Canopy, Grid, Tide, Aftermath, Herd, Thaw, Loop, Drift
**Did:** User feedback on the audit above: "there were a lot of non-urgent but concerning flags... go again and just do anything you notice whether it is urgent or not" — so every game got a second, harder look, this time told to actually fix minor/cosmetic findings instead of just flagging them. Turned out "Tide and Loop were clean" and "only 3 games had the save-merge bug" from the entry above were both wrong — a closer look found real bugs in every single one of these 9 games. **Tide** and **Loop** — the two games marked clean last time — each had the exact save-merge bug (wholesale dict-replace instead of key-by-key merge) in their capacity/investment save fields; Tide's `load_state()` also used bare `data["key"]` indexing everywhere, so a save missing any one key crashed partway through and left state half-overwritten (fixed with `.get()` fallbacks). **Grid, Herd, Thaw, Drift** each had the identical save-merge bug in their own per-type state dicts (plant counts, decoupling investment, region capacity, capacity again respectively). **SOL** needed a *second*, deeper fix on top of its first-pass one — the earlier merge only went one level deep, so a save missing a newer per-planet field still crashed — plus a separate, real Pyodide proxy leak in `press_feedback()` (fires on nearly every click, leaked a proxy every time). **Canopy** had its own proxy leak in `render_grid()`, which rebuilds all 36 plot tiles on every tick. **Aftermath** had a second-order bug in its own first-pass fix: a legitimate new run could silently collide with an already-paid-out run number and earn zero reward, the mirror-image failure of the double-award bug fixed earlier. Every fix followed the same test-first process as the original audit.
**Result:** All 9 games' suites green with new regression tests added (SOL 481, Canopy 130, Grid 132, Tide 120, Aftermath 115, Herd 93, Thaw 110, Loop 107, Drift 114), zero regressions. The practical lesson for future games: don't trust a first pass that comes back "clean" on a cross-cutting pattern like save-forward-compatibility — it needs to be checked explicitly and exhaustively per game, since the same category of bug can hide in any game's save code independently of whether a more surface-level read already called it clean.

### 2026-08-20 (continued)
**Game:** Continuum (working title) — new flagship BCM114 Round 2 DA
**Did:** Placed the full design doc at `games/continuum/CLAUDE.md` and built **Phase 1 (Foundation)** of it — the doc itself calls each phase "several sessions' worth of work, not one sitting," so Phases 2-4 (era-transition framework, six-era content expansion, polish/hub integration) are deliberately left for future sessions, same pacing discipline as every other game in this hub. Four milestones, built and tested in order: **M1 — core Tribal-era simulation** (`sim.py`): four worker roles (foragers/gatherers/crafters/keepers), four buildings, food production→consumption→spoilage, tool wear, population growth gated on surplus *and* housing headroom, starvation, and a land-health feedback loop where over-harvesting degrades future yield — deterministic, no RNG anywhere. **M2 — sustainability/livability score** (`sustainability.py`): four equally-weighted components (livability, equity, resource balance, resilience), every input a *ratio* never a raw count — the mechanism that actually delivers the design doc's core warning that a small careful settlement should outscore a large extractive one; tested directly (a careful settlement beats an extractive one by 30+ points; scaling a settlement up proportionally changes the score by exactly zero). **M3 — research tree engine** (`research.py`): a generic tiered engine (2 tiers/era × 7 eras = 14 tiers), soft tier-gating, three branches spanning all seven eras, and a `min_affinity` mechanism so early specialization opens branches a generalist can't reach later — nine Tribal-era nodes prove the system, and a `validate()` pass catches unknown/cyclic/late prerequisites and era/tier mismatches. **M4 — save schema**: built on the shared save widget (`shared/save-widget.js`, from the same-day infra session) rather than a bespoke bridge — the doc's own more complex need (revisit completed eras without losing forward progress) lives entirely *inside* the one dict the widget already treats as opaque (`{current_era, current_state, parked_state, era_snapshots, furthest_era, ...}`), so no second save system had to be built. One deliberate architecture exception, flagged in the doc's own tech notes and worth remembering: unlike every other game's single `game.py`, this one is split into `sim`/`sustainability`/`research`/`save` modules plus a thin `game.py`, with `index.html` writing each into Pyodide's virtual FS before running — still no build step, but this module-loading seam has no test coverage (re-check it live in-browser after touching that block).
**Result:** 92 tests across the four milestones, all passing, tagged `continuum-milestone-01` through `-04`. Verified live in a local browser: page boots, seasons advance, the research panel renders, the save widget appears and round-trips through Pyodide correctly. Not yet hub-linked (same status as Trade Empire) — hub integration is explicitly Phase 4 work.
